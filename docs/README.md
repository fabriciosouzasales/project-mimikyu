## Retomando este Projeto com uma Nova Sessão de IA

Este repositório é a única fonte de verdade do Project Mimikyu. Ele foi estruturado para que qualquer sessão de IA — inclusive uma sessão nova, sem memória de conversas anteriores — consiga retomar o projeto de forma confiável.

Ao iniciar uma nova sessão (por perda de contexto, início de uma nova fase, ou troca de ferramenta), utilize um prompt equivalente a este:

> Você está retomando o Project Mimikyu. O repositório oficial (`fabriciosouzasales/project-mimikyu`) é a única fonte de verdade — não presuma nenhuma decisão que não esteja explicitamente documentada nele, mesmo que pareça familiar. Antes de qualquer ação:
>
> 1. Leia `CLAUDE.md` (raiz do repositório) — convenções operacionais para qualquer agente de IA neste projeto (fluxo por ciclo, pareamento de SQL, estilo de histórico, ambiente).
> 2. Leia `docs/INDEX.md` — catálogo de toda a documentação, um resumo de uma linha por documento; use-o para decidir o que ler em profundidade, em vez de ler tudo de imediato.
> 3. Leia `docs/README.md` (este documento), incluindo a seção "Status Atual do Projeto", e `docs/ROADMAP.md` para a trajetória macro.
> 4. Leia `docs/log.md` (últimas entradas) para o que aconteceu recentemente.
> 5. Leia o handoff vigente em `docs/development/`, quando existir — ele é operacional (estado executado, arquivos alterados, validações pendentes, checklist de retomada), não normativo.
> 6. A partir daí, aprofunde apenas nos documentos numerados, ADRs (`docs/adr/ADR-INDEX.md`) e Standards (`docs/standards/STD-INDEX.md`) relevantes ao trabalho em questão — `docs/INDEX.md` existe justamente para evitar ter que ler tudo de uma vez.
> 7. Depois de ler o necessário, resuma a fase atual do projeto, as decisões já consolidadas e as pendências em aberto — e só então aguarde instruções para iniciar qualquer trabalho novo.
>
> Não avance com implementação ou com novas decisões de modelagem sem essa confirmação.

Este prompt funciona da mesma forma na fase de documentação e na fase de implementação — o que muda é apenas o papel assumido pela IA depois da confirmação. Decisões permanentes (ADRs) são imutáveis uma vez aprovadas; supersessões geram um novo número, preservando o histórico. **Atualizado em 2026-08-06** como parte da adequação ao padrão LLM Wiki (ver `CLAUDE.md`): o ritual anterior ("leia 00 até o último documento numerado, cada ADR, cada Standard") foi substituído por uma orientação em camadas via `CLAUDE.md`/`docs/INDEX.md`, mais barata para uma sessão nova.

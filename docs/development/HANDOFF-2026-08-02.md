## 3. Fluxo TCGdex (Ciclo 2 de `ADR-024`)

### Processador
- Edge Function `import-catalog-cards` (distinta de `import-card-assets`, que trata apenas imagens) — consulta a API TCGdex, normaliza os dados e grava `catalog_import_row`.
- `services/normalize.ts` — resolve raridade/categoria/etc. da TCGdex para os códigos canônicos internos, via `RARITY_NAME_ALIASES` (mapa de divergências de nome/gênero/idioma já observadas em dados reais — ver seção 6, abaixo).

### Telas
- `/catalogo/importar-cartas` — seleção de Coleção, análise (localização automática do Set via `external_set_id`), tabela de Revisão inline (sem navegação para página separada), ordenada por número de coleção ascendente, com ações por linha (aceitar/rejeitar/editar) e tooltips.
- `/catalogo/importar-imagens` — tela dedicada para importação de imagens por idioma (EN/PT-BR), com seletor de idioma, progresso ao vivo, retry automático.
- Continuação automática cartas→imagens: ao confirmar a gravação de cartas, o pipeline de imagens é disparado automaticamente para `pt-BR` (idioma que nunca era coberto pela via manual).

### Estado real do pipeline de imagens (evolução desde `HANDOFF-2026-07-31.md`)
Edge Function `import-card-assets` evoluiu de v2.6.0 (correção da máquina de estados nunca escrita) até **v2.9.3, CONFIRMADO DEPLOYADO**:
- v2.9.0 — idioma dinâmico via `asset_import_run.language_id` (suporte real e simultâneo a EN+PT-BR; `card_external_reference` ganhou `language_id` na chave de unicidade, Query `210` v2.0/Migration `277`).
- v2.9.1 — timeout de 20s no download de imagem (`AbortController`), corrigindo travamentos por download pendurado (causa raiz de um incidente real com `ME5`).
- v2.9.2 — corrige sobrescrita do erro real por uma mensagem genérica de transição de estado quando o retry automático do cliente tentava reabrir uma run já `FAILED`.
- v2.9.3 — retry automático por download individual de imagem (até 3 tentativas por carta, com classificação `retriable`/`não retriable` por tipo de erro), editado diretamente por Fabrício nos arquivos da função.
- Frontend: retry automático no cliente (mesmo `run_code`, reabre run quando necessário via sinal `runExpired`), contador "X de Y" ao vivo, aborto antecipado quando o padrão de falha é sistemático (0 sucesso em 15+ cartas processadas), exibição do motivo real de cada falha agrupado por causa.

Detalhe completo: `05-modelo-de-dados.md`, revisões `1.30`–`1.44`.

## 5. Limitações conhecidas

- Não existe orquestração automática de ponta a ponta para o Ciclo 2 além da continuação cartas→imagens já descrita — cada Coleção nova ainda depende de ações manuais na interface.
- `MEP` (Expansion `ME`) segue com imagens pendentes (`0`/`120`) — gap de dados na TCGdex nunca resolvido pela via manual (`scripts/import-manual-assets.ts`), sem relação com o Ciclo 2/TCGdex ingestion. Ver `ROADMAP.md`, Trilha 1.
- Teto de execução da plataforma (Edge Function, ~150s) segue existindo — cada tentativa de importação de imagens processa um lote parcial de uma Coleção grande; o retry automático do cliente existe justamente para compensar essa limitação, não para eliminá-la.
- Estratégia de múltiplas fontes externas (multi-provider) não decidida — só a TCGdex é usada hoje; instabilidade real já observada (HTTP 502 transiente em `ME5`) motivou o registro da pendência, sem solução aprovada. Ver `06-pipeline-importacao.md`, seção "Em Aberto".
- Auditoria consolidada de `GRANT`s para `service_role` em todo o schema `public` segue deliberadamente adiada.
